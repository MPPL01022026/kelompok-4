# Project Setup dan Deployment

## A. Membuat repository template
1. Buat repository baru di akun/organisasi kelas.
2. Unggah seluruh file proyek.
3. Buka **Settings → General → Template repository** dan aktifkan opsi template.
4. Teman sekelas dapat memilih **Use this template** untuk membuat repository mereka sendiri.

## B. Menyiapkan Supabase
1. Buat proyek di https://supabase.com/.
2. Buka Project Settings → API dan salin Project URL serta publishable key (atau anon key lama).
3. Masukkan nilainya di `js/supabase.js`. Key ini memang digunakan di browser; **jangan gunakan `service_role` key**.
4. Di Storage, buat bucket bernama `bakso-photos` dan aktifkan **Public bucket** agar foto dapat dilihat pengunjung.
5. Buka SQL Editor, lalu jalankan SQL berikut untuk membuat tabel dan kebijakan akses.

```sql
create table if not exists public.gallery_photos (
  id bigint generated by default as identity primary key,
  title text not null,
  description text,
  image_url text not null,
  storage_path text not null unique,
  uploaded_by uuid not null references auth.users(id),
  created_at timestamptz not null default now()
);

alter table public.gallery_photos enable row level security;

create policy "Anyone can read gallery photos"
on public.gallery_photos for select
to anon, authenticated
using (true);

create policy "Signed-in users can add gallery metadata"
on public.gallery_photos for insert
to authenticated
with check (auth.uid() = uploaded_by);

-- Storage: public read for images
create policy "Anyone can view bakso photos"
on storage.objects for select
to anon, authenticated
using (bucket_id = 'bakso-photos');

-- Only authenticated users may upload to this bucket.
create policy "Signed-in users can upload bakso photos"
on storage.objects for insert
to authenticated
with check (bucket_id = 'bakso-photos');
```

### Penting tentang pengelola
Contoh SQL di atas mengizinkan setiap pengguna yang berhasil login di proyek Supabase untuk mengunggah. Untuk penggunaan publik, batasi akun yang dapat login: di Supabase Auth, matikan pendaftaran publik jika tersedia pada konfigurasi proyek, buat akun pengelola secara manual dari dashboard, dan jangan bagikan kredensialnya. Untuk proyek produksi, tingkatkan kebijakan agar hanya user/role pengelola yang diizinkan upload dan insert metadata. Kebijakan Storage tambahan untuk menghapus/mengubah file belum dibuat.

Bucket publik membuat foto dapat diakses oleh siapa pun yang memiliki URL. Jangan unggah foto yang bersifat pribadi atau tidak memiliki izin.

## C. Menjalankan secara lokal
- Buka folder proyek di editor.
- Jalankan menggunakan ekstensi Live Server atau server HTTP statis.
- Buka URL lokal yang disediakan server tersebut.
- Uji galeri dan login setelah Supabase terkonfigurasi. Membuka `index.html` langsung melalui `file://` dapat menimbulkan masalah pada beberapa browser.

## D. GitHub Pages
1. Pastikan konfigurasi frontend sudah diisi.
2. Buka repository → **Settings → Pages**.
3. Pada Build and deployment, pilih deploy from branch, lalu branch utama dan folder root.
4. Simpan dan tunggu proses deployment selesai.
5. Buka URL Pages yang ditampilkan di Settings → Pages.

GitHub Pages hanya meng-host frontend. Supabase tetap diperlukan untuk database, autentikasi, dan file foto.

## E. Troubleshooting
- Galeri tidak termuat: cek URL/key, nama tabel, RLS, dan Console browser.
- Upload gagal: cek akun login, kebijakan Storage, bucket, format, dan ukuran file.
- Foto terunggah tetapi tidak muncul: cek kebijakan insert tabel dan `image_url`.
- Jangan pernah menaruh `service_role` key di `js/supabase.js`, HTML, atau kode frontend.
