# Resource & Responsibility Plan

## 1. Tujuan
Dokumen ini menjelaskan pembagian peran anggota, tanggung jawab utama, serta sumber daya yang dibutuhkan untuk proyek **Digitalisasi UMKM Bakso Jambo Langsa**.

## 2. Struktur Tim dan Tanggung Jawab

Pembagian di bawah merupakan rancangan awal. Kelompok dapat menyesuaikannya dengan pembagian kerja aktual dan persetujuan seluruh anggota.

| Anggota | Peran Utama | Tanggung Jawab | Hasil Kerja yang Diharapkan |
|---|---|---|---|
| Rani Simahbengi | Project Coordinator / Dokumentasi | Mengatur jadwal dan rapat, memantau progres, menjaga daftar tugas, mengoordinasikan review, serta memastikan dokumentasi perencanaan diperbarui | Jadwal, catatan progres, dan dokumentasi proyek |
| Anisa Aulia | UI/UX Designer / Analis Kebutuhan | Mengumpulkan kebutuhan pengguna, menyusun alur pengguna, merancang struktur halaman dan tampilan, serta memeriksa konsistensi antarmuka | Daftar kebutuhan dan rancangan UI/UX |
| Zaskia Lexsa | Frontend Developer | Mengembangkan struktur halaman, styling, navigasi, responsivitas, serta mengintegrasikan rancangan ke implementasi website | Halaman website yang responsif |
| M. Rizki Foenna | Integrasi / QA | Membantu konfigurasi layanan penyimpanan foto, memeriksa integrasi, menguji fitur dan tautan, mencatat bug, serta mendukung deployment | Integrasi teruji, daftar bug, dan hasil pengujian |

**Catatan:** Peran tidak membatasi kolaborasi. Seluruh anggota bertanggung jawab atas review, komunikasi, pengujian dasar, dan persiapan presentasi.

## 3. Matriks Tanggung Jawab (RACI)

- **R (Responsible):** mengerjakan aktivitas.
- **A (Accountable):** memastikan hasil akhir dan mengambil keputusan.
- **C (Consulted):** dimintai masukan.
- **I (Informed):** menerima informasi perkembangan.

| Aktivitas | Rani | Anisa | Zaskia | M. Rizki |
|---|:---:|:---:|:---:|:---:|
| Analisis kebutuhan | A | R | C | C |
| WBS dan jadwal | A/R | C | C | C |
| Desain UI/UX | C | A/R | C | I |
| Pengembangan frontend | C | C | A/R | C |
| Integrasi penyimpanan foto | I | C | R | A/R |
| Pengujian dan pencatatan bug | C | C | R | A/R |
| Deployment dan dokumentasi | A | I | R | R |
| Review dan presentasi | A/R | R | R | R |

## 4. Kebutuhan Sumber Daya

| Sumber Daya | Kegunaan | Rencana |
|---|---|---|
| Laptop/komputer | Pengembangan, pengujian, dan dokumentasi | Menggunakan perangkat anggota |
| Koneksi internet | Kolaborasi, akses repositori, deployment, dan layanan online | Menggunakan akses yang tersedia |
| Git dan GitHub | Version control, kolaborasi kode, serta penyimpanan dokumen | Repositori kelompok |
| Code editor | Menulis dan memeriksa HTML, CSS, JavaScript, dan Markdown | Menggunakan editor yang tersedia |
| Browser modern | Pengujian tampilan dan fungsi website | Chrome/Firefox atau setara |
| Hosting website | Publikasi website | GitHub Pages jika sesuai dengan konfigurasi proyek |
| Penyimpanan foto online | Menyimpan dan menampilkan foto yang diunggah | Layanan yang dikonfigurasi tim; verifikasi kuota, kebijakan akses, dan keamanan |
| Materi foto dan konten | Menampilkan menu, produk, dan informasi UMKM | Gunakan materi yang diizinkan pemiliknya |

## 5. Komunikasi dan Pelaporan
- Koordinasi dilakukan melalui kanal komunikasi yang disepakati anggota.
- Perubahan kode sebaiknya dicatat melalui commit yang jelas dan ditinjau sebelum digabungkan.
- Progres, kendala, dan risiko diperbarui pada saat koordinasi tim.
- Kredensial layanan, token, dan kunci privat tidak boleh dimasukkan ke repositori publik.

## 6. Persetujuan
Pembagian tugas dan sumber daya final ditetapkan setelah dikonfirmasi oleh seluruh anggota kelompok.
